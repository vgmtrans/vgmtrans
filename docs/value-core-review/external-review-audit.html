Independent review · 1 October 2026

Useful findings.
Unsafe combined patches.

The review found real defects. Its proposed fixes also introduced regressions. This audit checked the handoff against the unpatched branch at fd18ec966, reproduced the relevant behaviors, and implemented selected corrections. Neither supplied patch was applied wholesale.

The most consequential findings were incorrect pitch context during continued voices, pitch placement that could rewrite an earlier curve, modulation resets at tempo changes, and sample references crossing between private bank copies. These warrant corrections within the existing architecture.

Why the pitch guards needed replacement

Two examples require different results:

  • A note starts at 60 and follows an explicit 60→64 curve. A later 62→66 slide may start at 62 at its own command, but must leave the earlier curve untouched.
  • A Konami held note has nominal key 64 at tick 4, with a delayed 60→64 envelope beginning at tick 6. Its starting key belongs at tick 4, during the delay. The planner’s generated jump toward 64 is not an independent source slide.

The implementation asks which source note boundary the delayed curve belongs to and whether an earlier explicit curve already occupies that interval. Both rendering modes use this decision. Native conversion places any valid initial key before checking whether the future destination survives the hardware deadline. This also handles repeated tied keys whose ID stays the same while their source boundary changes.

This is a targeted correction. It adds a boundary/history query and native initial-key placement, while retaining the existing bend resolver. It does not claim to solve arbitrary concurrent channel-pitch intent or to simplify the entire pitch architecture.

The remaining bank problem is real

Raw bank numbers still serve several roles: source identity, logical bank selection, legacy SF2 projection, and percussion selection. For example, retained raw banks 1 and 256 can both become SF2 bank 1, while MSB-only MIDI maps raw 256 to bank 0. The narrower reservation fixes do not make that pair safe.

The patches’ solution—move every nonportable bank into 0–127—assumes melodic use. That breaks a supported percussion case: an SF2 preset at 128:5 is selected by a GS drum channel using program 5. Relocating the preset alone does not change the channel’s role. The checked-in FluidSynth source also explicitly selects its drum bank for a drum channel.

A complete fix should choose output addresses together with MIDI bank mode and channel role, then let both the MIDI and sound-bank writers consume that same plan. It must specify how stitching treats percussion and how a preset used on both melodic and percussion channels is represented. This audit preserves existing nonportable addresses instead of guessing that policy. Large-bank projection collisions therefore remain an open correctness issue.

Did the corrections compromise simplification?

The fixes made the supported behavior more correct, but did not themselves simplify the architecture. Their cost is real: pitch conversion now distinguishes source sensitivity from the instrument used by a continuing voice, and delayed initial placement from a later independent slide. Sample ownership and derived modulation updates also need distinctions that the old code omitted. Removing those distinctions would bring back the reproduced bugs.

Some of the implementation cost was avoidable. A follow-up cleanup removes 38 net production lines, leaving the corrections at +122 relative to fd18ec966. This is the cost of the review corrections and cleanup, not the total change from core-rewrite. No permanent test code was added in this cleanup.

  • Refer directly to note records. Stable note storage lets the ID lookup and preceding-voice link point to the same records. Numeric predecessor indexes and their translation helper disappear. The linear collection and constant-time lookup remain.
  • Decide modulation routing once. One decision selects oscillator simulation or synth controls. Delay, vibrato, pan, tremolo, and derived-update handling use that decision instead of separately repeating policy and layer checks.
  • Represent sample ownership as a choice. A sample belongs either to a selected bank occurrence or to a shared external asset. That replaces a redundant asset ID plus numeric scope and special sentinel. The input selections stay fixed while their addresses serve as private identities; these keys do not escape preparation.
  • Remove duplicated note initialization and source dispatch. Native onset and delayed targets share their final setup. Source sensitivity changes are interpreted directly in the source timeline; the pitch-context value no longer has a separate event-dispatch method.

Consolidating all native gate adjustments was investigated and rejected. A new slide must cap every still-overlapping fragment of its anchor, while physical planning transfers the gate from the immediately preceding attack of a held voice. For example, a long overlap at tick 2 followed by a short overlap at tick 4 must shorten both older fragments. Making one pass handle both jobs would require extra fragment history, rather than simply deleting a duplicate check.

The cleanup preserves output across 832 generated export cases: 576 MIDI pitch/gate cases, 192 modulation cases, and 64 SF2/DLS cases. Encoded bytes and diagnostic messages match b073bb77a exactly. The 43 Release suites and 13 focused reproduction groups pass. The 16,000-note probe still takes about 35 ms and produces the same MIDI bytes; it establishes no new speedup. Comparison sources, binaries, and logs are local under /tmp/vgmtrans-fix-cleanup/.

The result has less bookkeeping and fewer repeated decisions, with no new format-author responsibilities. Pitch-history interpretation remains the largest conceptual cost. A larger redesign would need to make that history explicit without adding another parallel representation; these small corrections do not establish that such a redesign would be worthwhile.
